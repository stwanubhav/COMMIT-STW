## What is this?

**GitHub Auto-Commit Tool** is a full-stack desktop-style web application that takes any local project folder on your computer and automatically uploads every file to a GitHub repository — one file at a time, each with its own intelligent commit message generated by an AI model from HuggingFace.

It solves a real problem: when you have a finished project sitting on your machine and you want to push it to GitHub properly, with a clean commit history instead of one giant "initial commit".

## ✨ Features

| Feature | Details |
|---|---|
| 🤖 AI Commit Messages | Uses HuggingFace `facebook/bart-large-cnn` to read each file and write a meaningful commit message |
| 🧠 Smart Fallback | If no HuggingFace token is provided, it uses a built-in heuristic engine that analyses file names, extensions, and code patterns |
| 🔍 Smart File Filtering | Automatically skips `node_modules`, build folders, binaries, secrets, and files over 5 MB |

| 📊 Real-Time Progress | Live progress bar, per-file status updates, and a full activity log |
| 🛑 Cancel Anytime | Stop the pipeline mid-run without breaking anything |
| 🌐 Runs in Browser | No desktop app installation needed — runs as a local web server and opens in your browser |
| 📁 Built-in Folder Browser | Navigate your filesystem inside the app to pick your project folder |

## ⚙️ How it Works

The pipeline runs in 6 clear steps when you click **Start Commit Pipeline**:

```
Step 1 — Validate GitHub Token
        ↓
Step 2 — Resolve Repository (create it if it doesn't exist)
        ↓
Step 3 — Scan Local Project Folder
         • Walk all directories recursively
         • Apply all filter rules (blocked dirs, extensions, .gitignore, size)
         • Build sorted list of committable files
        ↓
Step 4 — Analyse Project with HuggingFace AI
         • Send file list to AI for project-level summary
        ↓
Step 5 — For each file:
         • Read file content
         • Send to HuggingFace AI → get commit message
         • Base64-encode content
         • Check if file already exists on GitHub (for update vs create)
         • Commit the file with the AI-generated message
         • Wait 800ms (to avoid GitHub rate limits)
        ↓
Step 6 — Show summary (committed / failed / skipped)
```

All progress is streamed back to the browser in real time using **Server-Sent Events (SSE)**.

### Module responsibilities

**`server.js`**
- Serves the frontend static files
- Exposes `POST /api/start-commit` — streams progress via SSE
- Exposes `POST /api/cancel` — stops the running pipeline
- Exposes `POST /api/browse` — lists directories for the folder browser

**`src/commitOrchestrator.js`**
- The heart of the app
- Runs the full 6-step pipeline
- Calls `fileFilter`, `GitHubClient`, and `HuggingFaceClient`
- Emits structured progress events via callback

**`src/github.js`** — `GitHubClient` class
- `getAuthenticatedUser()` — verify token
- `resolveRepo()` — parse `owner/repo` or `repo`
- `ensureRepoExists()` — create repo if missing
- `commitFile()` — base64-encode and commit a single file
- `getFileSha()` — check if file exists (needed for updates)

**`src/huggingface.js`** — `HuggingFaceClient` class
- `generateCommitMessage()` — send file content to AI, get commit message back
- `analyseProject()` — generate a project-level summary from file list
- Automatic retry on model loading (503 responses)
- Built-in heuristic fallback engine

**`src/fileFilter.js`**
- `collectFiles()` — recursively walk directory, apply all filters, return sorted file list
- `isBinaryFile()` — detect binary files by scanning for null bytes
- `loadGitignore()` — read and apply project's `.gitignore`

## 🚀 Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/) version 18 or higher
- A **GitHub Personal Access Token** with `repo` scope
  → [Create one here](https://github.com/settings/tokens/new)
- *(Optional)* A **HuggingFace API Token** for AI commit messages
  → [Create one here](https://huggingface.co/settings/tokens)

### Install

```bash
# Clone or download the project, then:
npm install
```

### Run

```bash
npm start
```

The app starts at **http://localhost:3131** and opens in your browser automatically.

## 📖 How to Use

### Step 1 — Enter your GitHub Token
Paste your Personal Access Token in the **GitHub Token** field.
It needs the `repo` scope to create repositories and push files.

### Step 2 — Enter HuggingFace Token (optional)
Paste your HuggingFace API token for AI-generated commit messages.
If you skip this, the app uses smart heuristics instead (still works great).

### Step 3 — Enter Repository Name
Type the repo name in one of these formats:
- `my-project` — creates/uses a repo on your own account
- `yourusername/my-project` — uses a specific owner

### Step 4 — Select Project Folder
Click **Browse** to open the built-in folder browser.
Navigate to your project and click **Select This Folder**.
Or just type the full path directly into the field.

### Step 5 — Choose Options
- ✅ **Auto-create repo** — creates the repo if it doesn't exist yet
- ⬜ **Make repo private** — check this to make it a private repository

### Step 6 — Start!
Click **Start Commit Pipeline**.

Watch the progress in real time:
- **Progress bar** — shows overall % completion
- **File List tab** — each file turns green (✅) as it's committed
- **Activity Log tab** — full timestamped log of every action

### Done!
When finished, a summary card shows how many files were committed, skipped, and failed, plus a direct link to your GitHub repo.

## 🚫 What Gets Skipped

The filter is aggressive to keep your repo clean.

### Blocked Directories (never committed)
```
node_modules/     vendor/           .git/             .svn/
dist/             build/            out/              .next/
.nuxt/            __pycache__/      .pytest_cache/    venv/
.venv/            env/              target/           Pods/
coverage/         .cache/           .turbo/           .vercel/
.serverless/      .dart_tool/       .pub-cache/       tmp/
logs/             bower_components/ .gradle/          .nyc_output/
```

### Blocked File Extensions (never committed)
```
Compiled:   .pyc .pyo .class .o .obj .exe .dll .so .wasm
Archives:   .zip .tar .gz .bz2 .7z .rar
Media:      .mp4 .avi .mov .mp3 .wav
Secrets:    .pem .key .pfx .p12 .cer
Database:   .sqlite .db
Logs:       .log
```

### Blocked Filenames
```
.env   .env.local   .env.production   .env.development
.DS_Store   Thumbs.db   desktop.ini
```

### Size Limit
Any file **larger than 5 MB** is skipped automatically.

### Your .gitignore
Whatever rules are in your project's `.gitignore` are also applied.

## 🤖 AI Commit Messages

When a HuggingFace token is provided, each file goes through this process:

1. File content is trimmed to 800 characters (to fit model token limits)
2. A prompt is built: `File: src/auth/login.js\nLanguage: JavaScript\n\nCode: ...\n\nWrite a concise git commit message:`
3. The prompt is sent to `facebook/bart-large-cnn` via the HuggingFace Inference API
4. The response is cleaned and formatted as a proper commit message
5. If the API fails or is slow, the heuristic fallback kicks in

### Heuristic Fallback (no token needed)

The heuristic engine analyses file names and content patterns:

| Pattern detected | Example commit message |
|---|---|
| `readme` in filename | `Add project README documentation` |
| `test` / `spec` in path | `Add tests for userService` |
| `index.js` in a folder | `Add main entry point` |
| Class detected in code | `Add AuthController class implementation` |
| Multiple functions found | `Add utils module with 6 functions` |
| Config file | `Add webpack configuration` |
| `package.json` | `Add package.json with project dependencies` |
| `Dockerfile` | `Add Dockerfile for containerization` |

## ❓ FAQ

**Q: Does it overwrite files that already exist in the repo?**
Yes. It checks if each file already exists (using GitHub's `getContent` API to fetch the file SHA) and uses that SHA when updating. This is required by the GitHub API.

**Q: What if my GitHub token doesn't have the right permissions?**
The app validates your token and repo access before starting. You'll get a clear error message if something is wrong.

**Q: What if the HuggingFace model is loading (cold start)?**
The app automatically waits and retries once. HuggingFace free-tier models can take up to 20 seconds to warm up on first use.

**Q: Can I commit a project that already has a `.gitignore`?**
Yes. The `.gitignore` at the root of your selected project folder is automatically read and applied.

**Q: Why is there an 800ms delay between commits?**
GitHub enforces secondary rate limits on rapid API calls. The delay prevents your token from being temporarily blocked.

**Q: Can I push a project with thousands of files?**
Yes, but it will take time. At 800ms per file, 1000 files = ~14 minutes. You can reduce the delay or cancel and re-run at any time.
